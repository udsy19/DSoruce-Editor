## 1. The gate — `G11 Furniture agreement`

Two assertions, both geometry-to-geometry, both re-derived.

**1. Emission (count-exact).** Per room, the multiset the workbook's `Furniture Inventory` bills must
equal the multiset the gate derives *from the core state*: it re-runs the Rust generator in Node
(`scripts/lib/demo-doc.mjs`), buckets each component into a zone with its own implementation of the
core's rule (specific zone beats `Circulation`, smallest area wins), and builds `"Name Wxx X Lyy"`
from the component's own dimensions. Neither side is a producer summary.

**2. Visibility.** Emission is necessary but not sufficient — the E7 furniture *is* emitted, it is
painted over. So each billed instance must still read on the delivered PNG:

```
ink_per_outline = furniture-ink px inside the footprint / 2*(w_px + h_px)
```

Line-work ink scales with **outline length**, not area, which makes the measure cohort-free. That
mattered: my first attempt normalised each instance against its same-size siblings, and it was
**blind to rooms 145/147** — the pack's only two 0.6×0.6 tables are each other's only peer and *both*
were occluded, so the peer median was the defect. The outline model has no such hole.

The two ink classes are separated by hue, from the delivered pixels alone:
* furniture = cool-neutral (`#2e343b` / `#7c848e` and their blends) — **blue above green**;
* room label = pure neutral (`palette.json plan.room_label_text` is `#000000`, so its anti-aliasing
  is `r == g == b` exactly).

Blue-above-**green** rather than blue-above-red because furniture inside a circulation zone is
painted over by the pink wash, which lifts red only: `#2e343b` under the wash reads `(66,47,53)`.
My first classifier used `b > r` and so scored the dwg pack's three circulation-zone chairs at 0.00
**even after they were fixed** — a false failure I found by running the gate on all three packs, not
just the delivered one. `b > g` survives the wash and still excludes label ink on both backgrounds
(the wash multiplies green and blue by the same factor: `(255,230,230)` has `b-g = 0`). All numbers
below are the corrected classifier, re-measured in both directions.

The gate also asserts both classes are actually *present* and that its own re-derived world→canvas
transform lands the model inside the plate — so a change that makes the two inks indistinguishable,
or that changes the renderer's fit, fails loudly instead of silently measuring nothing.

## 3. The fix

`renderPlanCanvas` step 6 seeds `placeNear`'s `occ` with **every non-Door component's footprint in
canvas pixels** before the first label is placed, so labels de-collide against furniture ink and not
only against each other:

```ts
const occ: OccBox[] = []
for (const c of state.components) {
  if (c.category === 'Door') continue
  occ.push(componentBox(c, X, Y, k))
}
```

Labels are **displaced, never dropped, never shrunk** — room 163 already demonstrated the good
outcome and now every small room behaves like it. `plan-labels.json` still carries **22 labels, 22
unique**, and G3's "every Inventory Room ID appears exactly once" passes with its check count
unchanged (92).

## 5. Why `sheetSet.ts` had to change

With `occ` seeded, the dwg pack's open desk field (room 154, 162 instances) exhausted all 13 of
`placeNear`'s candidates, and the old fallback put the label back on the true centre — squarely on an
8 px chair (0.56, floor 0.70). The fallback now returns the **least-overlapping** candidate, so the
label lands in the widest gap it can reach; ties keep candidate order, so the layout stays
deterministic. Room 154 went **0.56 → 1.39**, and dwg's worst room is now 125 at 0.99 (was 0.00).
I looked at the crop: the 154 label sits in the aisle between two desk rows.

## 9. What I did not do

* **G9 does not run G11 per case.** G11 supports `--case seeded|testfit|dwg` and passes on all three
  today (§4), but wiring it into G9's per-case sweep is a change to another agent's gate; the brief
  scoped me to `run-all.sh`. Worth a follow-up — it is one line in `g9-roundtrip.py`.
* **The gate rebuilds the document by running the Rust core in Node** (~0.3 s). That is deliberate:
  it is the only ground truth upstream of every export. It means G11 needs `web/src/wasm` built —
  the same requirement `scripts/render-plan.mjs` and G9 already have.
* **`OS` is a real Room ID in the dwg pack** (three chairs outside every zone, billed under
  `takeoff.ts`'s `'OS'` catch-all). The gate grades it like any other room. Whether a client-facing
  takeoff should ever bill a room called `OS` is a product question, not this defect.
