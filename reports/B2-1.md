## 2. The API B3 codes against

One import, one call:

```ts
import { buildXlsx, pxToEmu, colName, type SheetSpec, type Cell, type StyleSpec } from './workbook'

const bytes: Uint8Array = buildXlsx(sheets /* SheetSpec[] */)   // sheet order == array order
```

### `SheetSpec`

```ts
interface SheetSpec {
  name: string                              // sanitised to <=31 chars, no []:*?/\ ; duplicates get " 2"
  rows?: Cell[][]                           // dense, row-major. rows[0][0] === A1
  cells?: Record<string, Cell>              // sparse overlay keyed by A1 address; WINS over `rows`
  cols?: Record<string, number | { width: number; hidden?: boolean }>   // 'B': 34.0
  rowHeights?: Record<number, number>       // { 5: 140 }  — 1-based row number -> POINTS
  merges?: string[]                         // ['Q4:R4']
  gridlines?: boolean                       // default true; false => <sheetView showGridLines="0"/>
  showRowColHeaders?: boolean               // default true
  freeze?: string                           // 'A5' freezes rows 1-4
  images?: SheetImage[]
  validations?: DataValidationSpec[]
  defaultRowHeight?: number                 // points
}
```

Use `cells` for the qbiq sheets (they are sparse: legend at Q4, body at B4, lookup at $J$9).
Use `rows` when you genuinely have a dense table. Mixing is fine and is how `takeoff.ts` does it.

### `Cell`

```ts
type Cell = number | string | null | undefined | CellSpec

interface CellSpec {
  v?: number | string | boolean | null   // literal value; for a formula cell this is the CACHED result
  f?: string                             // formula, leading '=' optional
  style?: StyleSpec
}
```

- A bare `number` → numeric cell. A bare `string` → `inlineStr`. `null`/`''`/`undefined` → nothing emitted.
- `f` wins over `v`. **Do not bother supplying `v` for formula cells** — the workbook carries
  `<calcPr fullCalcOnLoad="1"/>`, so Excel/LibreOffice/Numbers recompute on open. A stale cached
  `v` is provably overwritten (test: cached `0` → recalcs to `50000`).
- Formula text is XML-escaped for you: `'` `<` `>` `&` `"` are safe, so
  `IF(A1<>0,"",SUMIF('Inventory'!$L$1:$L$78,$C5,'Inventory'!$K$1:$K$78))` can be passed verbatim.
- **Formulas never carry a leading `=` in the file**; openpyxl reads them back **with** one
  (`c['C1'].value == '=A1*B1'`). That is exactly the shape `docs/reference/qbiq/spec/workbook-spec.json`
  records, so B3 can compare literally against the spec's formula strings.

### `StyleSpec`

```ts
interface StyleSpec {
  font?: { name?: string; size?: number; bold?: boolean; italic?: boolean; underline?: boolean; color?: Color }
  fill?: Color                      // SOLID fill. '#0B67F9' | '0B67F9' | 'FF0B67F9' | '#0BF'
  numFmt?: string                   // '@' | '0.00' | '#,##0.00' | '"₹"#,##0'
  border?: { all?: BorderEdge; left?: BorderEdge; right?: BorderEdge; top?: BorderEdge; bottom?: BorderEdge }
  align?: { h?: 'left'|'center'|'right'|'justify'|'fill'|'general'
            v?: 'top'|'center'|'bottom'|'justify'; wrap?: boolean; indent?: number; rotation?: number }
}
type BorderEdge = 'thin'|'medium'|'thick'|'dashed'|'dotted'|'double'|'hair'|'none'
                | { style: BorderStyle; color?: Color }
```

Styles are **content-deduped** — declare `const HEADER: StyleSpec = {…}` once as a module const and
reuse it on 500 cells; it costs one `<xf>`. Colours become direct `<fgColor rgb="FFxxxxxx"/>` — **no
`<indexedColors>` indirection**, so a palette hex reads back byte-exact (verified for all 7 chips).

### `SheetImage`

```ts
interface SheetImage {
  data: Uint8Array
  format: 'png' | 'jpeg' | 'gif'
  from: { col: number; row: number; colOff?: number; rowOff?: number }  // 0-BASED. B5 === {col:1,row:4}
  to?:   { col: number; row: number; colOff?: number; rowOff?: number }  // present => twoCellAnchor
  ext?:  { cx: number; cy: number }    // EMU. Used when `to` is absent => oneCellAnchor
  editAs?: 'oneCell' | 'twoCell' | 'absolute'   // twoCellAnchor sizing, default 'oneCell'
  name?: string
}
```

- **Indices are 0-based**, matching `workbook-spec.json`'s `from.col`/`from.row` fields directly.
  Column B is `col: 1`; row 5 is `row: 4`.
- `pxToEmu(px)` / `ptToEmu(pt)` convert. `pxToEmu(240) === 2286000`, `pxToEmu(180) === 1714500` —
  the reference's exact thumbnail extent, asserted in the test.
- **Media is deduped by content**: pass the same logo bytes on 11 sheets and exactly one
  `xl/media/image1.jpeg` part is written (verified: 5 sheets, 6 image placements, 4 media parts).
- Drawing parts are only created for sheets that have images, and are numbered independently of
  sheet index — so `dropdowns` having no logo costs nothing.

### `DataValidationSpec`

```ts
interface DataValidationSpec {
  type: 'list' | 'whole' | 'decimal' | 'date' | 'time' | 'textLength' | 'custom'
  formula1: string          // inline: '"cm,m,f,inch"'   |   range: 'dropdowns!$A$1:$A$4'
  formula2?: string
  operator?: 'between'|'notBetween'|'equal'|'greaterThan'|'lessThan'
  sqref: string | string[]  // ['M9:M12','K3','C3'] or 'M9:M12 K3 C3'
  allowBlank?: boolean
  showDropDown?: boolean    // reads the SANE way: default/true = arrow visible
  errorTitle?: string; error?: string; promptTitle?: string; prompt?: string
}
```

**Gotcha handled for you:** OOXML's `showDropDown="1"` actually *hides* the arrow. The API inverts it —
leave `showDropDown` alone to get a visible dropdown (which is what the reference has, despite openpyxl
reporting `showDropDown: false`).

## 4. Design notes B3 must know

1. **`fullCalcOnLoad="1"` is on by default** (`buildXlsx(sheets, { fullCalcOnLoad: false })` to disable).
   This is why we do not need to compute cached values in TS. G2's recalc harness (openpyxl save →
   soffice convert) works because of it.
2. **Worksheet element order is strict** and handled internally:
   `dimension → sheetViews → sheetFormatPr → cols → sheetData → mergeCells → dataValidations →
   pageMargins → drawing`. Getting this wrong is the #1 cause of Excel repair prompts; it is now
   impossible to get wrong from the API.
3. **Fill index 0 and 1 are reserved** by the format (`none`, `gray125`). Handled; your first custom
   fill lands at index 2.
4. **One `<col>` per letter** is emitted rather than min/max ranges, because openpyxl's
   `ws.column_dimensions['B'].width` only resolves per-letter entries — and G1/G5 read it that way.
5. **Number formats** are always allocated as custom ids from 164 up, even for codes that have a
   builtin id. openpyxl reads back the *code* (`'@'`, `'0.00'`), which is what the spec records, so
   this is invisible to gates.
6. **`v: null` with a `style`** is how you emit an empty-but-coloured cell (the legend chips). A cell
   with neither value, formula nor style is skipped entirely.
7. Duplicate sheet names are auto-suffixed rather than throwing — check your names, B3.

## 5. What did not work / open risks

- **`shared` formulas are not implemented.** Every formula is written out in full (`<f>A1*B1</f>`).
  For ~1000 formula cells this is a few tens of KB of XML — irrelevant in STORE mode, and it is what
  the spec extractor reads anyway. Not a gap, just a non-goal.
- **No `sharedStrings.xml`** — every string is an `inlineStr`. Correct and universally read, but a
  workbook with tens of thousands of repeated strings would be larger than Excel's own output. At
  12 sheets × ~80 rows this is a non-issue.
- **No `docProps/`** (title/author/created). Nothing in the gate suite reads it. If the orchestrator
  wants a branded Properties dialog, that is ~15 lines in `buildXlsx`.
- **No conditional formatting, no defined names, no charts, no autofilter, no print setup.** None are
  in the reference's 12 sheets. `freeze` is implemented (unused by the reference).
- **`ZIP64` is not implemented** (inherited from `zip.ts`). The container caps at 4 GB / 65 535
  entries. With 34 media parts and 12 sheets we are ~4 orders of magnitude clear.
- **Risk — image byte provenance.** G5 fails if two rooms of *different types* share byte-identical
  thumbnails, and our media table de-dupes by content. That de-dup is a *consequence*, not a cause:
  if C's renderer emits a placeholder, the workbook will contain one media part referenced 31 times
  and G5 will correctly fail. Do not read a low `xl/media/*` count as a writer bug — it is the
  renderer telling the truth.
- **Risk — `showDropDown` inversion.** If B3 ever mirrors the spec JSON's `showDropDown: false`
  literally into the API, the arrows will be *hidden*. The spec field is openpyxl reporting the raw
  attribute; the API field means what it says. Just omit it.
- **Stale doc line (not mine to regenerate):** `scripts/gates/lib/gen_spec_md.py:198` still prints
  "`takeoff.ts` hand-writes OOXML (`sheetXml`/`takeoffToXlsx`) and emits **only** …". Those symbols
  are gone and the claim is now false. Agent A owns that generator — one-line fix on its next run.
- `takeoff.test.mjs` still hardcodes a stale scratchpad path from a previous session's session-id.
  It works (it `mkdir -p`s), but `workbook.test.mjs` uses `os.tmpdir()` instead; worth aligning
  whenever someone touches that file.
