## 2. The material-theme API — what E and F code against

```ts
import {
  buildInteriorScene, createMaterialTheme,
  createInteriorLighting, interiorEnvironment, interiorSkyTexture,
  floorKeyForZone, floorMaterialNameForZone, FLOOR_MATERIAL_NAME,
  type MaterialTheme, type InteriorScene, type InteriorRoom,
} from '../three/materialTheme'
```

### The three calls that give you the look

```ts
const scene = buildInteriorScene(state, { wallSpans, plate })  // → { root, theme, floors, rooms, plate, bounds, dispose() }
viewer.setContent(scene.root)                                  // EXISTING Viewer3D API — no fork
// …later
scene.dispose()
```

```ts
const lights = createInteriorLighting({ focus: { x, y, radius } })  // THREE.Group: hemi + sun + fill + ceiling luminaires
scene.add(lights)

const envRT = interiorEnvironment(renderer)   // RoomEnvironment PMREM — the shared IBL
scene.environment = envRT.texture
scene.environmentIntensity = 0.42
scene.background = interiorSkyTexture()       // the daylight the perimeter glazing looks out on
```

`buildInteriorScene` returns a plain `THREE.Group`, so **E's walkthrough and F's web viewer get the
identical look by dropping it into `Viewer3D.setContent()`** — no second scene builder, no second
theme. `InteriorSceneOpts` toggles `perimeterGlazing` / `ceiling` / `luminaires` / `exterior` and
accepts a pre-built `theme` so a viewer can rebuild the scene without rebuilding materials.

### Renderer settings E and F should match (or the four deliverables will not look alike)

```ts
renderer.toneMapping        = THREE.NeutralToneMapping   // NOT ACES — see §5
renderer.toneMappingExposure = 1.15
renderer.outputColorSpace   = THREE.SRGBColorSpace
renderer.shadowMap.enabled  = true
renderer.shadowMap.type     = THREE.VSMShadowMap         // PCFSoftShadowMap is deprecated in three r185
scene.environmentIntensity  = 0.42
// composer: RenderPass → GTAOPass → OutputPass → SMAAPass  (Viewer3D's 'render'-tier order)
```

`three/interiorStill.ts` exports `placeRoomCamera(scene, room, state, opts)` and
`renderInteriorStill(scene, camera, opts)`; **E can reuse `placeRoomCamera` for its keyframes** — it
is the piece that guarantees a camera is not inside a wall.

### Per-room data on `scene.rooms: InteriorRoom[]`

`zone` · `finishKey` · `floorKey` · `floorMaterialName` (the Inventory name) · `center` · `bbox` ·
`focus` (furniture centroid) · `components` · `accentWall` (midpoint of the room's sage/slat/bronze
identity wall, when it has one).

## 3. The anti-drift chain (the actual point of the deliverable)

```
palette.json ─► qbiqPalette.MATERIALS ─┐
                                       ├─► materialTheme ─► the rendered pixels
FINISH_SPEC[finishTypeFor(zone)].floor ─┘        │
        (the Inventory sheet's own source)       └─► RoomRender.floorMaterial ─► ground-truth.renders ─► G6
```

`floorKeyForFinish()` collapses the India-market finish spec onto qbiq's two-material floor
vocabulary — **anything matching `/carpet/i` is `Carpet Light Gray`, every hard floor (stone,
timber, vinyl, tile, screed) is `Parquet Herringbone - dark`** — derived from `FINISH_SPEC` at call
time, so editing the finish schedule moves the renders automatically. The split independently
reproduces `palette.json`'s own `usedFor` notes (parquet for "reception, open-space and lounge
floors", carpet for "conference rooms, offices, focus rooms, workstation zones").

**B3: `floorMaterialNameForZone(zone)` is the function your Inventory `Floor Material` column should
use.** If it does, G6's cross-check is unfailable by construction.

### The floor sample is measured, not asserted

Every still renders a second **mask pass** (same camera, flat colours, no post) in which white is
*only the target room's own floor plate*. A full sweep over that mask picks the largest crop that is
≥97 % floor and correctly exposed; that crop is what goes into `ground-truth.renders[].floorRect`.
Three things this catches that a fixed bottom band does not:

* **glazing occludes in the mask.** Looking into a room from a neighbouring one crosses four glass
  surfaces, each laying a near-white film over what is behind it — measured, that turned a floor of
  H 21 / S 0.23 / L 0.28 into H 20 / S 0.06 / L 0.61. Only floor the camera sees *directly* may be
  sampled.
* **shadowed floor is not a material sample.** A crop that is 97 % floor but sits in the black under
  a table reports the ambient, not the finish (measured S 0.09 vs a 0.18–0.48 band).
* **a still that cannot evidence its floor says so.** `RoomRender.floorCheck` is `'ok'`,
  `'no-clean-floor'` or `'floor-underexposed'`; only `'ok'` stills carry a `floorMaterial` claim into
  ground truth. G6 then notes the skip rather than being handed an unsupportable assertion.

## 4. Camera auto-placement

Eye at **1.60 m**, horizontal FOV **70°** (75° in rooms under ~7 m diagonal, 62° for the close
workstation shot) — inside the brief's 60–75° band. Candidates are every door threshold (in and
stepped back out), every room corner and wall midpoint, stand-off points outside each face, and an
interior grid for rooms big enough to step into. Each is validated before it can win:

1. **containment** — the eye may not sit inside any upright solid's world AABB;
2. **clearance** — 8 horizontal + 2 vertical probes must be clear;
3. **reachability** — the view must run unobstructed for most of the way to the subject;
4. **coverage** — ≥20 % of a 3×3 probe grid over the room must be in frame and unoccluded;
5. **frame clutter** — <45 % of a 21-ray frustum grid may hit something inside 1.6 m;
6. **floor visibility** — how much of the lower frame lands on the room's own floor, directly;
7. **accent wall** — a tie-breaker for facing the room's identity surface.

> **A correction worth recording:** the "am I inside a wall?" test was originally a ray-parity count,
> which is **unsound in this scene**. Every material is `FrontSide`, so three culls back faces: a ray
> crossing a closed box reports *one* hit, not two, and a ray fired from *inside* a box reports none
> at all. It was rejecting good meeting-room corners as "inside a solid" while being blind to the one
> failure mode it existed to catch. It is now an exact AABB containment test.

`node scripts/render-rooms.mjs --camera-debug` prints every candidate's score or rejection reason.

## 5. Where I improved the render tier rather than faking it

* **Khronos PBR-Neutral tone mapping instead of ACES.** ACES' RRT deliberately crosstalks channels;
  a controlled test with a *pure red* albedo rendered `#994A4A` — equal green and blue lifted to
  74/255, which no diffuse colour can produce. That drift is fatal for a render whose contract is to
  agree with a materials takeoff. PBR Neutral exists to keep a material's colour recognisable through
  tone mapping.
* **Killed the floor's specular.** The same red test isolated the rest of the lift as environment
  specular: at roughness 0.42 / envMapIntensity 0.45 the parquet mirrored the bright interior IBL
  hard enough to bury its own chroma (S 0.10 vs a 0.18–0.48 band). At 0.95 / 0.06 the red test
  returned `#7C211F` (S 0.60) and the parquet returned to H 20.9 / S 0.31 / L 0.27 — mid-band.
* **Luminance-only floor colour map.** A brown parquet texture multiplies its own hue in and then
  dominates: rotating the albedo 10° moved the rendered floor 0.5°. The map now carries plank tone,
  joints and grain as luminance, and hue/chroma come entirely from the calibrated albedo.
* **VSM soft shadows.** `PCFSoftShadowMap` is deprecated in three r185 and silently degrades to hard
  PCF (it warns on every render). VSM's blur is a real filter over the depth distribution.
* **Luminaires that actually emit.** Ceiling lights sit on the *same 2.4 m grid the recessed
  downlights are drawn on*, so the render is lit by the ceiling it shows. An enclosed meeting room
  gets no sun at all; on ambient alone its floor rendered a stop and a half under the same material's
  open-plan reading, and the two stills then disagreed about a material they share.
* **Real door openings.** Doors are subtracted from their wall span with a lintel above — which is
  what lets a threshold camera see into a room instead of at a blank slab.
* **Sun shadow frustum fitted to the room in shot**, so a 4096 map resolves a 5 m meeting room
  instead of smearing over a 40 m plate.

No post-process filter is applied over a flat image anywhere.

## 7. Honest visual assessment — I looked at every render

I read all four PNGs as images at every iteration, not just the statistics.

**Open_space — good.** The strongest of the four. Reads immediately as an open-plan office: oak bench
desks receding down the floor, black linear pendants over each desk run, a recessed downlight grid, a
white glazed room band on the left, perimeter glazing with a green landscape on the right, and a
believable carpet. Depth and vanishing point are right. *vs the reference:* the reference has a
sculpted rectangular ring luminaire, a bronze perforated library wall, sage acoustic pods, planting,
bar stools and real chairs. Ours is the same room type, plainer — maybe 60 % of the way there.

**Work_stations — good.** A wider, lower view across the desk banks toward the glazed facade; the
white glass-fronted rooms and a timber door anchor the left. Honest, well exposed, no artefacts.
*vs the reference:* the reference is a tighter, more intimate desk-level shot with iMacs, Aeron
chairs, plants and a perforated bookcase wall. Ours has no chairs at all (see risk 1) and reads
emptier and more diagrammatic.

**Reception — decent, and the best of the small rooms.** Shot from the corridor through the glazed
front: the sage-green feature wall, both suspended black ring luminaires, the parquet floor, an oak
door, daylight down the left, and the corridor's parquet in the foreground. It genuinely reads as a
designed reception. *vs the reference:* the reference reception is a much larger, richer space
(circular timber insets in the sage wall, a fluted reception desk, tub chairs, a rug, planting). Ours
is a small glass-fronted room with a table in it. The composition is a fairly flat elevation of a
glass box rather than an inhabited interior.

**Conference_room — the weakest, and I am not hiding it.** A corner-of-the-room view: table edge in
the lower left, a large blank wall filling the upper left, a linear pendant, the glazed wall and the
bronze screen beyond on the right. It is correct and artefact-free, but it is a boring photograph:
too much blank plasterboard, and the table dominates the near field. *vs the reference:* the
reference shoots its conference room from the corridor through the full glass wall and gets the whole
table, chairs, screen wall, timber slats and the city view. **The demo document's meeting room is
5 × 4 m; no camera at 1.6 m inside a 5 × 4 m room with a 2.4 m table can produce the reference shot.**
The corridor shot *is* available and does look better — I deliberately did not take it, because that
still would then have no directly visible floor and would forfeit its Inventory cross-check (see the
trade-off in risk 3). On a real GCC floorplate with 20–30 m² meeting rooms this camera produces a
good frame; I verified the logic is not the limitation by rendering seed 11.

Defects I can see and have NOT hidden: no chairs at the desks; the exterior view is a flat green
band rather than a landscape; the perimeter glazing is milky; there is no planting, no signage, no
people; the ceiling is a single flat plane with no bulkheads. None of these are gate failures — they
are the honest gap between a parametric test-fit renderer and a hand-modelled Enscape scene.

## 8. Open risks

1. **No chairs at the desks.** The demo document has 63 desks and 9 chairs — that is the *document's*
   truth. Adding chairs for the picture would put furniture in the render that is not in the takeoff,
   i.e. exactly the drift this deliverable exists to prevent, so I did not. **This is a core/layout
   issue, not a render issue:** if `layout.rs` emitted a task chair per desk, the stills would improve
   markedly and the QTO would get more accurate at the same time.
2. **The `Reception` still does not evidence its floor material.** 3 of 4 stills carry the Inventory
   cross-check (the brief's stated bar is 3). The reception's floor pixels arrive through its glazed
   front, and I will not sample a material through glass. If 4/4 is wanted, raise `INSIDE_BONUS` in
   `interiorStill.ts` from 1.5 to ~3.0: the camera moves inside the reception, all four stills gain
   the claim, and the reception becomes a much worse photograph (table edge + blank wall). One line,
   explicit trade-off.
3. **Perimeter glazing is a documented rendering convention, not a quantity.** The shell renders as a
   0.9 m spandrel with a glazed band above, because the core classifies a bare shell run as
   `perimeter_wall` only when the document carries no `Window` components (C-1 §8.3) and a windowless
   office render would be wrong. **No quantity is taken from this geometry.** `perimeterGlazing:
   false` gives a solid shell.
4. **Palette calibration constants are tuned against this renderer.** `LIGHT_GAIN`, `SAT_BOOST`,
   `HUE_TRIM_DEG` and the parquet's roughness/envMapIntensity are calibrated so the *rendered* surface
   lands inside `palette.json`'s measured band — each carries the measurement that justifies it in a
   comment. Change the tone mapping, the exposure, or the IBL intensity and they must be re-measured
   against G6. **E and F: use the renderer settings in §2 verbatim or your output will drift from
   mine and from the spec.**
5. **Hardware GL vs SwiftShader.** The harness launches Chromium with `--use-angle=metal` and gets a
   real Apple M4 Pro Metal context. On a machine without it, the renderer detects the software
   rasterizer and drops GTAO (the same guard `Viewer3D` uses). The stills will render slightly flatter
   there; I have **not** verified G6's luminance band on a SwiftShader-only host.
6. **`Open_space` and `Work_stations` share one zone.** This test-fit has no separate lounge, so both
   resolve to the open workspace and are differentiated by framing — which is exactly what the
   reference pack does. A plan with a real `Collaboration` zone ≥25 m² will split them automatically.
7. **`scene.dispose()` is conservative on purpose.** It frees only geometry this module allocated;
   `buildFurniture3D` hands back groups over module-level shared geometry/materials that the live
   `Viewer3D` and `sectionRender` also use, and disposing those would blank every other consumer.
