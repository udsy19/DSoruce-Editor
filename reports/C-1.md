## 1. The API Agent B3 codes against

Everything is a plain-`DocState` browser-canvas call. **No wasm import** — the caller
passes the core's results in, so the module runs identically in the app and in the
headless harness.

```ts
import {
  renderHighlightedPlan, planRoomList, canvasToPngBytes,
  PLAN_W, PLAN_H, CIRCULATION_ROOM_ID,
  type PlanRoom, type PlanGraphicOpts, type PlanGraphicResult,
} from './planGraphic'
import { renderRoomThumbnail, renderAllRoomThumbnails, THUMB_W, THUMB_H } from './roomThumbs'
import { classifyWalls, type WallSpan } from './wallTypes'
import { PLAN_LEGEND_CHIPS, WALL_TYPE_HEX, PLAN_PALETTE, WORKBOOK_CHROME } from './qbiqPalette'
```

### The two required signatures

```ts
renderHighlightedPlan(state: DocState, opts?: PlanGraphicOpts)
  : Promise<{ png: Uint8Array; labels: string[] }>

renderRoomThumbnail(state: DocState, roomId: string | number, opts?: RoomThumbOpts)
  : Promise<Uint8Array>
```

### `PlanGraphicOpts`

| field | type | default | note |
|---|---|---|---|
| `width` / `height` | `number` | `1040` / `780` | the reference `xl/media/image1.png` size |
| `scale` | `number` | `1` | `2` → 2080×1560 @2x plate |
| `roomRefs` | `Map<number,string>` | – | **`App.tsx#buildRoomRefs(zones, markers)`** — Space-step markers beat generated zone ids, exactly as the Inventory does |
| `rooms` | `PlanRoom[]` | `planRoomList(state, roomRefs)` | **pass your Inventory rows here and G3 cannot fail** |
| `circulation` | `CirculationScore \| null` | – | `editor.circulation()`. Degenerate with 0 walls → pass `null`; the wash is guarded either way |
| `plate` | `[number,number][] \| null` | wall bbox | `editor.plate_polygon()` — clips the wash on irregular plates |
| `wallSpans` | `WallSpan[]` | `classifyWalls(state)` | pass `classifyWalls(state, editor.wall_types())` |

### `RoomThumbOpts`
`width`(240) · `height`(180) · `scale`(**1** — natural size == anchor size on purpose,
see §5) · `roomRefs` · `wallSpans`.

### The call B3 should actually write

```ts
const wallSpans = classifyWalls(state, editor.wall_types())   // core truth, not the fallback
const circulation = state.walls.length > 0 ? editor.circulation() : null
const plate = editor.plate_polygon()
const rooms = planRoomList(state, roomRefs)                    // === your Inventory rows

const { png, labels } = await renderHighlightedPlan(state, { circulation, plate, wallSpans, rooms })
const thumbs = await renderAllRoomThumbnails(state, { roomRefs, wallSpans })  // [{ id, png }]
```

`labels` is every Room ID drawn, in draw order → write it to `ground-truth.json`
`planLabels`. `thumbs[i].id` is the Inventory `Room ID` for the anchoring row.

### The room set — one function, both consumers

`planRoomList(state, roomRefs)` is the canonical list for the plan labels **and** the
Inventory sheet. It mirrors the reference workbook's own shape (31 rows = 30 rooms +
1 `Circulation`):

* every zone except `Circulation` and `Core` → `id = roomRefs.get(zone.id) ?? zone.id`
* **plus one aggregated circulation row, `Room ID "0"`** (`CIRCULATION_ROOM_ID`),
  anchored on the largest circulation zone — the reference's row 35 exactly.

If your Inventory derives its rows differently, pass them as `opts.rooms`; the label
list is then identical by construction.

### Legend chips — import, never transcribe

```ts
for (const { cell, label, hex } of PLAN_LEGEND_CHIPS) { /* Q5..Q11, R = label */ }
```
`PLAN_LEGEND_CHIPS` is `palette.json`'s own `_legendChipOrder`, and my linework uses
`WALL_TYPE_HEX` built from the same object. G4 compares the two for **exact** equality,
so using this constant makes that check unfailable. `WORKBOOK_CHROME` carries the
header/body fills from the same source.

## 2. Colour truth — how drift was made impossible

`web/src/export/qbiqPalette.ts` **imports `docs/reference/qbiq/spec/palette.json`
directly** (`import palette from '../../../docs/reference/qbiq/spec/palette.json'`).
No generated copy, no transcription, no build step to forget. Verified through all
three toolchains that matter:

```
esbuild (headless harness)  ✓  bundles and renders
vite dev  http://localhost:5199/src/export/qbiqPalette.ts
   →  import palette from "/@fs/…/docs/reference/qbiq/spec/palette.json?import"   HTTP 200

```

The circulation wash uses `palette.plan.circulation_source.rgba` = `rgba(255,0,0,25)`,
composited **once** through a `destination-out` mask so no pixel is ever double-washed
(stacking would drift the hue off the `#FFE6E6` legend chip). Core is `#A0A0A0` per the
orchestrator's ruling; the reference's `#D5BDD6` chip is not reproduced.

## 3. Wall classification — the core is the classifier

`web/src/export/wallTypes.ts` → `classifyWalls(state, coreTypes?)` returns `WallSpan[]`.

**Precedence:** `coreTypes` (from `Editor.wall_types()`, i.e. `crates/ds-core/src/quantity.rs`)
› `DocWall.wall_type` if the core ever inlines it into `state()` › the local fallback.

B1's classifier **has landed and is already wired**: `scripts/render-plan.mjs` calls
`ed.wall_types()` and hands it to `classifyWalls(state, wallTypes)`, so the coloured
plan and the workbook's wall quantities come from one source. Measured on the demo doc:

```
core wall_types: {"perimeter_wall":4,"drywall":65,"glass":20}
```

The fallback (used only when no wasm editor is in reach) derives from `glazing` → glass,
`Core` zone adjacency → core, plate-boundary adjacency → perimeter, else drywall — and
splits a bare perimeter run into solid corner returns plus a glazed band. **That split
is a drawing convenience, not a quantity** — never take wall lengths from the fallback.
`half_drywall` has no document signal yet, so it draws zero pixels (the reference plan
uses zero of it too) and remains a legend-only class until the core reports partition
height.

## 5. Thumbnails

240×180 **natural** pixels (`scale: 1` default). Deliberate: the reference's `ext` is
2286000×1714500 EMU = 240×180 px, and G5 measures the *anchor*, so natural == anchor
means even a naive embed passes. `scale: 2` is available for a retina embed, but then
you must anchor explicitly at 240×180.

Each thumbnail draws: floor swatch (`FINISH_SPEC[key].floor` → a `palette.materials`
hex, lightened) + a material module grid (carpet 0.5 m, tile 0.3 m, timber board 0.19 m,
screed 0.6 m) · the room's own furniture (`component_ids`, falling back to
point-in-zone) with a soft offset shadow · walls in their `WallType` colour · a
room-type accent bar and the Room ID. The `Room ID "0"` circulation row gets the
corridor network at flat `#FFE6E6` with 1.2 m of flanking context so it reads as a
corridor between rooms, not a bare band.

**22 rooms → 22 distinct images, no two byte-identical at all** (stronger than G5's
"not across different types").

## 6. Headless execution — one renderer, two hosts

`scripts/render-plan.mjs`:

1. `scripts/lib/demo-doc.mjs` runs the **real Rust core in Node** (`initSync` off a
   `Buffer`; wasm-pack `--target web` works fine) → `state`, `circulation()`,
   `wall_types()`, plate, seed 7.
2. esbuild bundles `planGraphic.ts` + `roomThumbs.ts` + `wallTypes.ts` (IIFE).
3. Playwright headless Chromium executes that bundle against a real `<canvas>`.
4. Artifacts written.

There is **no Node-only fork of the renderer** — the browser export action calls the
same exported functions with the same arguments. `demo-doc.mjs` is reusable by Agents
D/E/B3 for the same seeded document.

```
$ node scripts/render-plan.mjs

```

Artifacts: `out/plan.png` · `out/plan.repeat.png` · `out/plan@2x.png` (2080×1560) ·
`out/thumbs/<RoomID>.png` × 22 · `out/plan-labels.json` (`{ seed, labels, rooms }`).

## 8. Open risks

1. **G4/G5 depend on B3's workbook.** Two hard requirements on B3: legend chips from
   `PLAN_LEGEND_CHIPS` (exact hex equality), and thumbnails anchored in **column B**
   at **240×180** on rows **≥120 pt** (reference uses 180). Anything else and the gates
   fail on B3's side, not mine.
2. **Room-ID agreement.** G3 asserts every Inventory Room ID appears exactly once in
   `planLabels`. Safe only if the Inventory uses `planRoomList` (or passes its rows as
   `opts.rooms`). The aggregated `Room ID "0"` circulation row must exist in the
   Inventory or the counts diverge.
3. **`perimeter_windows` currently draws zero pixels** on the demo doc — the core
   classifies a bare shell run as `perimeter_wall` because the document carries no
   `Window` components. G4 does not test for it, and imported CAD with real windows
   will populate it. Cosmetic vs the reference (which is mostly windows).
4. **`half_drywall`** has no document signal (see §3). Legend row exists, zero pixels —
   same as the reference plan.
5. **The circulation wash is `plate − enclosed rooms`, not the evaluator's grid.**
   `Editor.circulation()` returns scalars only (`grid_cols`/`grid_rows`/`cell_size`,
   no mask), and re-deriving the occupancy grid in TS would be a second evaluator —
   a no-bloat violation. I use the core-emitted `Circulation` zones plus the residual
   free plate, and gate the wash on the evaluator's own output. **If the core ever
   exposes the walkable mask, it drops into `renderPlanCanvas` step 2 as the stencil
   source with no API change.**
6. **Room 153 (the open workspace)** spans the whole floor, so its thumbnail crop
   includes the pods sitting inside its bbox. Honest, but a reader may expect a tighter
   crop. Would need boundary-conforming workspace zones to fix.
7. **Tier 2 (3D perspective crops via `three/sectionRender.ts`)** was not attempted —
   it is explicitly gated on "only after all gates pass", and G4/G5 still depend on B3.
