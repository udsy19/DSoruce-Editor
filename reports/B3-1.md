## 3. How the workbook is wired

`General` is the only place a number or a name is stated. Everything else references it.

| Sheet | Cols | Body |
|---|---|---|
| Plan | Q4:S11 | plan PNG at A1→M37 · legend chips Q5:Q11 from `PLAN_LEGEND_CHIPS` · labels R · **measured run S = `='General'!L{9..14}`** |
| Furniture Inventory | B..J | one row per room+item · `J{r} = H{r}*I{r}` |
| Furniture Inventory Summary | B..G | `E = SUMIF` over the sheet above · `F = INDEX/MATCH` unit price · `G = E*F` |
| Inventory | B..N | 240×180 thumb in B · areas as **literals** (G3 reads the cells) · Floor/Ceiling Material from `FINISH_SPEC` |
| General | B..X | heights row 5 · 5 merged bands row 7 · catalogs from row 9 · 3 validations → `dropdowns` ranges |
| Main Summary | B..I | the union of the five BOM bodies (25 rows), identical formulas |
| BOM × 5 | B..I | 8 floors · 9 ceilings · 5 walls · 1 glass · 2 doors |
| dropdowns | A..F | the six source lists |

Every BOM body row:
```
B  =IF(ISBLANK(C5),"",'General'!$B$7)
C  ='General'!B9                                        ← direct ref: rename propagates
D  =IF(ISBLANK(C5),"",VLOOKUP(C5,'General'!$B$9:$E$16,2,FALSE))
E  =IF(ISBLANK(C5),"",VLOOKUP(C5,'General'!$B$9:$E$16,3,FALSE))
F  =IF(ISBLANK(C5),"",SUMIF('Inventory'!$L$5:$L$26,$C5,'Inventory'!$J$5:$J$26))   area
   =IF(ISBLANK(C22),"",'General'!$D$5*(VLOOKUP(C22,'General'!$J$9:$N$14,3,FALSE))) linear
   =IF(ISBLANK(C28),"",VLOOKUP(C28,'General'!$T$9:$X$10,4,FALSE))                 count
G  0                                                    ← the ONE literal: user override
H  =IF(ISBLANK(C5),"",VLOOKUP(C5,'General'!$B$9:$E$16,4,FALSE))
I  =IF(ISBLANK(C5),"",H5*IF(G5>0,G5,F5))
```
Formula density is **100 %** across `Main Summary` + all five BOM sheets (300/300 cells in B–E, H–I).

**Nothing is re-derived in TypeScript.** Wall runs, door counts and room areas are `Editor.quantities()`
verbatim; `General!D5` and `H5` carry `quantities.wallHeightM` (2.60 m — the core's constant, the same
one `Viewer3D` extrudes at), never a hard-coded 3.0.

### Room-set alignment (trap #2), solved once

`planRoomList(state, roomRefs)` is called by the plan renderer, the thumbnail renderer **and**
`buildQtoModel`, with the same `roomRefs`. The Inventory rows, the ground-truth `rooms` and
`planLabels` are therefore one set by construction — G3's 1:1 check cannot drift.

`Editor.ground_truth_json()` is **not** used, and this is deliberate (B1's open risk 3): the core emits
one entry per *zone*, including `Core` and every individual `Circulation` zone, while the Inventory
drops `Core` and aggregates all circulation into the single `Room ID "0"` row the reference itself uses
(its row 35). 22 rows vs 24 zones — G3 would fail three different ways. `buildQtoGroundTruth` filters
that room set **once**, in the same function that writes the Inventory rows; walls, doors and
`sqfPerM2` still come straight off `quantities()`. **`Editor::ground_truth_json` now has no caller**
(§7, risk 1) — B1's lane, flagged rather than touched.

## 5. Deviations from the reference (all deliberate, all evidenced)

**Reference bugs not replicated** (2 flagged by Agent A, 1 new):
1. `Main Summary` B7/B9/B14 → `C5` and B8/B10/B13/B15 → `C6` instead of their own row. Emitted consistently.
2. `BOM - Glass Partitions` header on row 5. Ours is 4/5 like every other BOM sheet.
3. **New.** Floors/Ceilings quantity is headed `Quantity Amount (m^2)` and the unit type is `m^2`, but
   the reference sums `Inventory!$K` — the **sqf** column (`J5=12.58, K5=135.3608`). Off by the
   conversion factor. We sum `$J` (Area m²), matching the header, the unit type and the ₹/m² material
   bank. Same class of slip as #1.

**Design deviations:**
4. `I = H*IF(G>0,G,F)` instead of the reference's `I = H*G` on area rows. With `G` shipping as a
   literal 0, the reference's floor and ceiling rows cost **zero no matter what price you type** —
   which contradicts the one thing this deliverable exists to do. Linear rows already used `H*F`.
5. **No `ROUND(...,2)` on the quantity column** (display `numFmt '#,##0.00'` instead). ROUND makes the
   recalc arithmetically inexact; on a short wall run the ±0.005 error can exceed G2's tolerance.
   Same on-screen result, exact arithmetic.
6. **`General!D5 = 2.60`, `H5 = 2.60`** (the core's `FULL_WALL_HEIGHT_M`), not qbiq's 3.0 / 2.98.
   Theirs are their assumptions; 2.60 is what our 3D viewer builds.
7. **Six wall types, not four.** `J9:J14` = the core's legend set (`Drywall`, `Half Drywall`, `Glass`,
   `Core`, `Perimeter windows`, `Perimeter wall`) — G3 checks this both ways. The reference's `Columns`
   row has no analogue in our model.
8. **`Glass` is billed on `BOM - Glass Partitions`, not `BOM - Walls`** (at glazing height `H5`, per the
   reference), so the Walls BOM has 5 rows while the Walls *table* keeps all six for the ground truth.
   The Glass Partitions block's length is `Q9 = =L11` — a **reference**, so the two can never drift and
   nothing is double-counted in the Main Summary.
9. **Validations point at `dropdowns` ranges** (`dropdowns!$B$2:$B$5` …) instead of inline literals —
   Agent A's own recommendation; same UX, and the wiring is inspectable. `showDropDown` omitted (B2's
   inversion trap).
10. Core legend chip `#A0A0A0`, per the orchestrator's ruling, via `PLAN_LEGEND_CHIPS` — the same
    object C's linework uses, so G4's exact-equality check is unfailable by construction.
11. Item Description is `"{Label} W{w} X L{l}"` (the existing `takeoff.ts` format, which satisfies the
    spec's own regex) rather than the reference's `"{Label} {CatalogFamily} W… X L…"` — our catalog
    label *is* the family, so the latter reads "Desk Desk".
12. Cost Code carries a real per-category code (`FF-DSK`, `FF-CHR`, …); only Supplier falls back to
    "Can be customized". The reference leaves both as that placeholder.
13. One brand mark on all 11 data sheets (the reference ships two different logo JPEGs). Media is
    content-deduped → **one** `xl/media` part for 11 placements.
14. Inventory column B is 36 chars (fits the 240 px thumbnail) not 70; rows are 140 pt not 180 —
    still above G5's 120 pt floor and above the 135 pt the image needs.

**Could not reproduce — and why, with evidence:**
- **`Half Drywall` = 0.00 m** on every plan. The document carries no partial-height signal
  (`Wall.height_m` exists but nothing sets it — B1-1 §3). The legend row and the catalog row are
  present and priceable. *The reference is in the same position:* Agent A measured **0 pixels** of
  `#72BDA1` in its plan and its own `General` walls table has no Half Drywall row.
- **`Perimeter windows` = 0.00 m** on all three cases: the core classifies a bare shell run as
  `Perimeter wall` because no `Window` components exist in these documents (C-1 §8.3). Cosmetically
  unlike the reference, whose facade is mostly glazed. Real imported CAD with window entities will
  populate it; the row, the chip and the BOM line already exist.
- **`renders`** is absent from `ground-truth.json` — that block belongs to the render agent. My writer
  now **preserves an existing `renders` key** rather than clobbering it (§6.2).

## 6. Two bugs found in other people's work

### 6.1 `workbook.ts` twoCellAnchor extent — real, worked around in my lane, NOT patched
`drawingXml` (workbook.ts:665) derives the picture's `spPr` extent as
`to.colOff − from.colOff` / `to.rowOff − from.rowOff` when `ext` is absent. That is only correct when
the anchor starts and ends in the **same** cell. For anything spanning columns or rows it produces a
near-zero box, and LibreOffice renders it: the 1040×780 master plan became **19 × 3 px**. B2's own
test never caught it because its plan image was checked with openpyxl (which reports the *native* px
of the media, not the anchor) and never rasterised.

I did **not** edit `workbook.ts` (B2's frozen lane). `qtoWorkbook.ts` passes an explicit
`ext: { cx: pxToEmu(1040), cy: pxToEmu(780) }` alongside `to`, with the reason in a comment.
**Recommendation for whoever unfreezes it:** the fallback should account for the intervening columns
and rows, or `ext` should be required whenever `to.col !== from.col || to.row !== from.row`.

### 6.2 `out/ground-truth.json` is written by two agents
G6 reads the `renders` block out of the same file my generator writes. `scripts/export-pack.mjs` now
reads any existing file first and carries `renders` through. **Order still matters if the render agent
does the same in reverse** — worth a one-line note in the orchestrator log.

## 7. Open risks

1. **`Editor::ground_truth_json` now has no caller.** Deliberate (§3) — its room set is every zone,
   which cannot satisfy G3 against a `planRoomList`-based Inventory. It is B1's lane and its tests
   still pass, so I left it. Either delete it, or move the room-set filter into the core and have
   `buildQtoGroundTruth` call it (the better fix, and B1 asked for exactly this decision).
2. **`QtoOptions.unitPrices` has no caller.** It is the brief's "opt-in pre-fill mode" and the module's
   documented extension point, but nothing in the app passes it today, so every unit price ships as 0
   (the honest default — the material bank prices furniture, not drywall runs or floor finishes).
   Delete it if the orchestrator would rather not carry an unused option.
3. **29 s for a 49-zone imported plan.** All of it is canvas work — 26 room thumbnails plus two full
   plan renders, each re-running `renderPrintCanvas`. Acceptable for a deliverable export, but it is a
   blocking main-thread loop with no progress UI. A spinner (or an `OffscreenCanvas` worker) is the
   obvious follow-up.
4. **`generate()` is far less seed-sensitive than assumed** — 10 seeds on the demo plate produce only
   **2** distinct layouts. This does not affect any gate (I gave the testfit case a different brief),
   but it means `autoGenerate`'s seed loop is exploring far less than its iteration count suggests.
   Worth someone's attention outside this mission.
5. **`scripts/gates/lib/gen_spec_md.py` is now stale on two more counts** (§4). Agent A's lane; not
   invoked by `run-all.sh`, so no gate is affected.
6. **The `dwg` case needs LibreDWG's `dwg2dxf` on PATH** (`/opt/homebrew/bin/dwg2dxf` here). Without
   it `buildDwgDoc` throws and only two of G9's three cases can be produced. Same dependency the
   VPS `/api/dwg` route already has; Vercel degrades it to 503 (CLAUDE.md).
7. **G10 still fails** — correctly. `data-testid="export-deliverable-pack"` now exists and the action
   fires client-side, but the gate also requires `out/renders/*`, `out/walkthrough.mp4` and
   `out/share.json`, which are agents D/E/F. It also requires the artifacts to land **in `out/`**,
   which a browser download cannot do; someone owns the decision of how the one click writes there
   (a dev-server sink, or G10 pointing at the downloaded zip).
8. The Plan sheet's legend straddles a page break when *printed* (the plan is 13 columns wide). On
   screen — how the workbook is actually read, and how the reference behaves too — Q4:S11 is one
   contiguous block. Not gated; noted for completeness.
